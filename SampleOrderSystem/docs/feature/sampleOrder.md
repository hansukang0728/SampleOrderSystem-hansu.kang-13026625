# 시료 주문 (Sample Order)

> 참조: [PRD.md](../../PRD.md) — O-01

---

## 1. 개요

고객이 시료를 요청하면 주문담당자가 시스템에 주문을 생성한다.  
주문 생성 시점의 상태는 **RESERVED** (접수 대기).  
승인·거절 처리는 `OrderManager` 기능에서 별도로 수행한다.

---

## 2. 주문 생성 흐름

```
메인 메뉴 → [2] 시료 주문
  → 시료 ID 입력
  → 시료 존재 확인
  → 고객명 입력
  → 주문 수량 입력
  → 유효성 검증
  → 주문번호 자동 생성 (ORD-YYYYMMDD-XXXX)
  → 상태: RESERVED
  → data.json 저장
  → 결과 출력
```

---

## 3. 입력값

| 항목 | 타입 | 제약 | 설명 |
|---|---|---|---|
| 시료 ID | string | 등록된 시료 ID (`S-NNN`) | 존재하지 않으면 오류 |
| 고객명 | string | 필수, 공백 불가 | 주문자 이름 |
| 주문 수량 | int | >= 1 | 요청 수량 (ea) |

---

## 4. UI 흐름 예시

```
============================================================
      시료 주문
============================================================
시료 ID (예: S-001): S-001
  → [S-001] 알파-시료 | 재고: 100ea | 여유

고객명: 홍길동
주문 수량 (ea): 30

------------------------------------------------------------
  주문번호 : ORD-20260508-0001
  시료     : S-001  알파-시료
  고객명   : 홍길동
  수량     : 30 ea
  상태     : RESERVED
------------------------------------------------------------
✔ 주문이 접수되었습니다.
```

---

## 5. 주문번호 생성 규칙

```
ORD-YYYYMMDD-XXXX
     │         └─ 당일 순번 (4자리 zero-padding, 0001부터)
     └─ 주문 생성 날짜
예) ORD-20260508-0001
```

---

## 6. 유효성 검증 규칙

| 항목 | 검증 조건 | 오류 메시지 |
|---|---|---|
| 시료 ID | 등록된 시료여야 함 | `"존재하지 않는 시료 ID입니다."` |
| 고객명 | 비어있지 않아야 함 | `"고객명을 입력해주세요."` |
| 주문 수량 | >= 1 | `"주문 수량은 1 이상이어야 합니다."` |

---

## 7. 생성 후 상태

- 주문 상태: **RESERVED**
- 재고 변화: **없음** (승인 시 처리)
- 저장: `data.json` write-through
